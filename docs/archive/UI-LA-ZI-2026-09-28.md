## Rangarea finală — cele 5 cu beneficiu maxim

Criterii: semnalul de cerere din research-ul verificat (voturi/HN/sondaje),
 potrivirea cu primitivii existenți (costul slice-ului inițial), teza de
produs (verificarea e blocajul, nu codarea).

1. **Diff review față de bază git, cu comentarii pe care agentul le citește
   înapoi** (ne-făcut; 5 categorii + Sonar 38%). Primele felii: diff read-only
   în Files pane (primitivele CodeBlock/Markdown există deja), comentariu pe
   fișier/hunk → composer; revenirea rămâne la Git/CLI per decizia proprietarului.
2. **Citări pentru browserul ca sursă: ancorare la pasaj** (parțial → rest).
   Transformă rezultatele de pagină citite/selection în surse [N] cu aceeași
   infrastructură WebResearch; grounding verificabil e cel mai iubit pattern
   (Comet 4.8/5, NotebookLM). Gate-ul Read există deja per tab.
3. **Consum inspector v2** (parțial → rest). Semnalul cel mai lat (8/9
   categorii; furia #1 = surprizele de cost și rutarea ascunsă). Slice ieftin:
   distincția estimat/raportat, avertisnă la prag de cheltuială, agregarea
   per worker din log-urile locale.
4. **Tasks ca obiect de lucru** (ne-făcut; worktree amânat). Owner/run,
   write-back al rezultatului worker pe task, status „needs input” pe task
   alimentând coada de atenție deja livrată — verificarea devine acțiune.
5. **Aprobări v2: decizii memorate + jurnal de acțiuni** (ne-făcut; standard
   EXPECTED). „permite mereu exact această operație” cu listă editabilă,
   jurnal per conversație (operație, URL, nivel de permisiune la momentul),
   confirmare per acțiune sensibilă în Full.

Amânări explicit: checkpoint/undo (decizie proprietar: Git/CLI, nu istoric
propriu); automatizări programate (depinde de 5 și de continuitate); memoria
itemizată (doar după controalele de review/invalidare); resume CLI și backup/
restore (infrastructură, nu UI — urmărite separat).
